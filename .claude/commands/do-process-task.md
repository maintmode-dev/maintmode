# Do Process Task

Выполнение задач из директории `.agent_tasks` с готовым планом. Эта команда используется после того, как задача была проанализирована командой `/do-analize-task`.

## Роль агента

При выполнении задач агент действует как **senior-разработчик с 5-летним опытом работы** на технологическом стеке проекта (см. `.agent/quick_load.toon`):
- Backend: Go 1.25.0+, Echo, PostgreSQL, jet, sqlx, goose
- Deployment: Docker

## Важно: Задача должна быть проанализирована!

Перед выполнением задачи она **ОБЯЗАТЕЛЬНО** должна пройти этап анализа и планирования с помощью команды `/do-analize-task`.

### Как проверить, что задача готова к выполнению:

1. ✅ В директории задачи есть файл `task.md` с детальным планом
2. ✅ В директории задачи НЕТ файла `task.draft.md` (черновик удален после согласования)
3. ✅ План согласован с пользователем

### Если задача НЕ готова к выполнению:

**Признаки**:
- Отсутствует файл `task.md` или он содержит только краткое описание
- Есть файл `task.draft.md` (план еще не финализирован)
- Нет детального плана выполнения с оценками времени

**Что делать**:
1. Сообщить пользователю что задача требует анализа
2. Предложить использовать команду `/do-analize-task task-name`
3. **НЕ НАЧИНАТЬ** выполнение задачи

**Пример сообщения**:
```
⚠️  Задача "task-name" не готова к выполнению!

Задача должна быть проанализирована перед началом работы.

Пожалуйста, запустите сначала анализ задачи:
   /do-analize-task task-name

После согласования плана вы сможете выполнить задачу используя:
   /do-process-task task-name
```

## Структура задач

Задачи организованы в директории `.agent_tasks/`:

```
.agent_tasks/
├── todo/              # Задачи к выполнению
│   └── task-name/     # Директория задачи
│       ├── task.md    # Финальный план (после анализа)
│       ├── materials/ # Дополнительные материалы (опционально)
│       ├── 1-subtask-setup/      # Подзадача 1 (опционально)
│       │   ├── task.md
│       │   └── materials/
│       ├── 2-subtask-implementation/  # Подзадача 2 (опционально)
│       │   └── task.md
│       └── 3-subtask-testing/    # Подзадача 3 (опционально)
│           └── task.md
├── done/              # Завершенные задачи
└── backlog/           # Задачи в резерве
```

## Workflow выполнения задачи

### Шаг 1: Подготовка (ВСЕГДА в начале)

1. **Загрузить контекст проекта** используя команду `/load-context`
2. **Проверить текущую ветку**: `git branch --show-current`
   - Если на main/master - создать feature branch
   - Если на feature branch - продолжить работу
3. **Найти задачу**:
   - Если пользователь указал имя - использовать эту задачу
   - Если не указал - показать список доступных задач

### Шаг 2: Проверка готовности задачи

**ОБЯЗАТЕЛЬНАЯ ПРОВЕРКА**:
1. Проверить наличие `task.md` в директории задачи
2. Проверить отсутствие `task.draft.md` в директории задачи
3. Прочитать `task.md` и убедиться что это детальный план (не краткое описание)

**Если проверка не пройдена** - остановиться и сообщить пользователю (см. раздел "Если задача НЕ готова к выполнению" выше)

**Если проверка пройдена**:
1. **Проверить наличие подзадач**:
   ```bash
   find .agent_tasks/todo/task-name -type d -name "*-subtask-*" | sort
   ```
2. **Прочитать task.md** и все дополнительные материалы
3. **Определить стратегию**:
   - Если есть подзадачи (`n-subtask-*`) → выполнять их последовательно по номерам
   - Если нет подзадач → выполнять как единую задачу

### Шаг 3: Выполнение задачи

1. **Создать TodoWrite список**:
   - Если есть подзадачи → добавить каждую подзадачу с кратким описанием
   - Если нет подзадач → разбить задачу на этапы из плана

2. **Выполнить задачу/подзадачи**:
   - Следовать всем правилам проекта (см. `.agent/quick_load.toon`)
   - Соблюдать naming conventions (branch, commit, code)
   - Следовать критериям готовности из плана
   - Обновлять TodoWrite по мере выполнения

3. **Для каждой подзадачи** (если есть):
   - Отметить в TodoWrite как in_progress
   - Выполнить подзадачу полностью
   - Отметить в TodoWrite как completed
   - Перейти к следующей подзадаче

### Шаг 4: Проверка и коммит

1. **Запустить тесты**: `make test`
2. **Запустить линтер**: `make lint`
3. **Зафиксировать изменения кода**:
   ```bash
   git add .
   git commit -m "feat(scope): описание изменений

   🤖 Generated with [Claude Code](https://claude.com/claude-code)

   Co-Authored-By: Claude <noreply@anthropic.com>"
   ```
4. **Обновить документацию** (если требуется) - отдельным коммитом:
   ```bash
   git commit -m "docs(scope): обновление документации"
   ```

### Шаг 5: Завершение задачи

1. **Переместить задачу** из `.agent_tasks/todo/` в `.agent_tasks/done/`:
   ```bash
   mv .agent_tasks/todo/task-name .agent_tasks/done/
   ```
2. **Обновить связанные tracking файлы** (если есть)
3. **Сообщить пользователю** о завершении

## Примеры использования

```bash
# Выполнить конкретную задачу

```

## Проверки безопасности

Перед выполнением любой задачи:
- ✅ Работа на feature branch (НЕ на main/master)
- ✅ Контекст проекта загружен (`/load-context`)
- ✅ Задача прошла анализ (есть `task.md`, нет `task.draft.md`)
- ✅ План выполнения понятен и детален
- ✅ Если что-то неясно - запросить уточнение

Перед коммитом:
- ✅ Тесты проходят (`make test`)
- ✅ Линтер проходит (`make lint`)
- ✅ Нет закомментированного кода
- ✅ Нет debug-вывода
- ✅ Нет чувствительной информации (secrets, tokens)
- ✅ Документация обновлена (если требуется)

## Обработка ошибок

### Если задача заблокирована

1. Отметить проблему в TodoWrite (статус `in_progress` остается)
2. Создать новую задачу описывающую блокер
3. Сообщить пользователю о блокере
4. Дождаться решения перед продолжением

### Если тесты или линтер не проходят

1. **НЕ помечать задачу как completed**
2. Исправить ошибки
3. Запустить тесты/линтер снова
4. Только после успеха пометить как completed

### Если реализация частичная

1. Сохранить статус `in_progress`
2. Описать что сделано и что осталось
3. Спросить у пользователя как продолжить

## Особенности workflow

### TodoWrite интеграция

При работе с подзадачами:
- Создать список TodoWrite с кратким описанием каждой подзадачи
- Каждая подзадача - отдельный todo item
- Пример:
  ```
  ✓ 1-subtask-database: Создание схемы БД и миграций
  → 2-subtask-api: API endpoints для auth
  ☐ 3-subtask-middleware: Middleware для защиты routes
  ☐ 4-subtask-tests: Тесты для auth системы
  ```

### Дополнительные материалы

Задача может содержать дополнительные материалы:
- Диаграммы
- Примеры кода
- Схемы БД
- API спецификации
- Скриншоты

Все материалы хранятся в директории задачи (или в поддиректориях типа `materials/`, `schemas/`, etc.)
